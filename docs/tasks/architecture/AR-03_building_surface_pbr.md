# AR-03: building wall and roof surfaces get full PBR with anti-tiling

Board row: **R-961**. Priority: high. Depends on: none - starts immediately.

## Player-facing goal

A limestone wall reads as cut and coursed stone, a plastered wall reads as lime render over rubble, a
log wall reads as tarred pine, a tile roof reads as fired clay and a thatch roof reads as reed - all
under the same sun, at the same distance, without the player having to guess from the tint. Wet stone
answers rain differently from wet thatch. No wall shows a repeating square grid when the camera pulls
back down a street.

## Why this is needed

`scripts/map/view3d/map_view_building_materials.gd` builds every wall and roof surface as:

- albedo: `_weathered_albedo(color, weathering)` returning a single `Color`, with
  `material.vertex_color_use_as_albedo = true` - so there is **no albedo texture at all**;
- normal: `MapViewMaterialPatterns.pattern_normal_texture(pattern, noise_seed)` - a procedurally
  generated bump pattern;
- roughness: `material.roughness = 1.0`, hard-coded, for every material on every building.

With roughness pinned at 1.0 and no roughness map, nothing in the built environment has varying
specular response. That is the single biggest reason stone, lime, tar and clay all read as the same
matte substance with a different hue, and it is independent of geometry - it will still look generic
after AR-04 and AR-05 unless it is fixed.

`assets/materials/pbr/building_variants/` already proves the fix is affordable: 21 albedo+normal pairs
across 7 families (tile, shingle, thatch, rubble, render, limewash, log), generated by
`tools/generate_building_surface_variants.py`. But it has exactly one consumer,
`MapViewBurgherHouseSurfaceVariety`, which only serves the **43** tiered houses in `lower_town_slice`,
and **not one family ships a roughness map**.

## Deliverable

1. **Roughness (and AO where it reads) added to all existing `building_variants` families**, generated
   by `tools/generate_building_surface_variants.py` so it stays reproducible. Each stem gains
   `*_roughness.png`, packed per the project's existing ORM convention
   (`tools/assets/prop_orm_baking.py`) rather than a fourth loose file if that convention applies.
2. **New families** so every `wall_material` and `roof_material` value in `content/maps/*.rrmap` has a
   real surface set, not a tint. Measured need from the authored maps: `limestone` 49 uses, `plank` 43,
   `log` 41, `plaster` 22, `timber` 3, `smoked_plaster` 2, `brick` 1; roofs `shingle` 64, `thatch` 37,
   `tile` 31, `straw` 1. Missing families to add, 3 stems each:
   - `ashlar_*` - cut and coursed limestone for elite and ecclesiastical fabric, distinct from `rubble`
   - `plank_*` - vertical and horizontal board walls, distinct from `log`
   - `daub_*` - wattle and daub infill for timber frame
   - `brick_*` - the single brick wall and future Hanseatic brick detail
   - `straw_*` - straw thatch, distinct from reed thatch
   - `soot_*` - smoked plaster / smoke-room interior face
   - `gable_board_*` - boarded gable field, which reads differently from the wall below it
3. **Anti-tiling.** A detail-blend path so a large wall or roof plane does not repeat: either a second
   octave at a different scale with a stochastic offset, or triplanar / hex-grid sampling. It must be a
   shader-side addition with a uniform that can be turned off, and must be free at the `minimum`
   quality tier if it costs anything measurable.
4. **Library reaches every building.** The surface-variety lookup becomes available to
   `map_view_building_materials.gd` for **all** building records, not only `house_tier=` ones, keyed
   deterministically by `(map_seed, building_id)` so the same map always looks the same. Flat vertex
   colour stays as the documented fallback for any family with no set, and a test asserts the fallback
   is unreached for the materials the maps actually use.
5. **Weathering stays cheap.** The existing comment in `map_view_building_materials.gd` - that one
   unique plate per roof was load-heavy, and that the weathering band must not multiply normal-map
   memory - is a hard constraint. Weathering keeps modulating a shared set; it does not fork textures.
6. `assets/SOURCES.csv` rows for every new texture, and a note that generation is reproducible from
   `tools/generate_building_surface_variants.py`.

## Constraints and non-goals

- Asset freeze P0-040: exactly the files above.
- **No geometry.** Not one vertex of any building changes here. AR-04 and AR-05 own geometry. This task
  must be provable as a pure surface change.
- No map, blueprint, transition, collision or navigation edits. No ID changes.
- Do not fork the material cache per building. Material count per map must not grow more than the ADR
  0022 budget allows; if AR-02 has not landed yet, hold the current material count and record the
  measurement so AR-02 can set the number.
- Do not exceed the storage policy. If the full set does not fit, ship fewer stems per family rather
  than lower channel counts, and say so in the report.
- `roughness = 1.0` may remain the fallback constant; it may not remain the behaviour for limestone,
  plaster, log, plank, tile, shingle or thatch.

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --script tools/run_godot_tests.gd -- --filter=test_building_surface_pbr,test_building_materials,test_burgher_house_models

python3 tools/validate_asset_sources.py && python3 tools/verify_asset_lint.py && python3 tools/verify_storage_hygiene.py
python3 tools/verify_map_composition.py && python3 tools/verify_map_audit.py
python3 tools/generate_active_docs_report.py --check
```

- `test_building_surface_pbr.gd` asserts: every `wall_material` and `roof_material` value present in
  `content/maps/*.rrmap` resolves to a surface set with albedo, normal **and** roughness; no building
  material in an authored map falls back to flat vertex colour; roughness is not the constant 1.0 for
  any of those families; stem selection is deterministic per `(map_seed, building_id)`; the anti-tiling
  uniform toggles; material count per compiled map stays within the recorded budget.
- `test_generate_building_surface_variants.py` asserts the generator is deterministic and emits the full
  channel set for every stem.
- A **geometry no-op proof**: the `MapParitySnapshot` / map-audit fingerprint for every compiled map is
  byte-identical before and after. State it in the report.
- `tools/capture_ar03_building_surfaces.gd` through `tools/godot_render.sh`: a material line-up plate
  (one plane per family, same light), and matched before/after plates of `lower_town_slice` and
  `north_quarter` at the gameplay camera - clear noon, overcast, rain, and midnight - on both
  Compatibility and Metal, at `minimum` and `recommended`.
- Performance: `tools/run_performance_report.sh --quick` on `lower_town_slice` and `north_quarter`, with
  the before/after frame cost of the anti-tiling path recorded.
- **Named human visual review** that stone, lime, tar, clay and reed are now distinguishable without
  the tint, and that no street shows a repeating grid. Green tests alone do not close this task.
