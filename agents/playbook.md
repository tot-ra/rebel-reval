# Shared agent playbook

Read this file together with the role-specific `agents/rebel-*/playbook.md` before working.
This file contains only cross-role operating lessons. Domain lessons belong to the agent that owns that work.

Keep this file short. Append a durable reusable rule, not a dated incident log. If the same lesson already exists, do not add another dated copy.

## Shared workflow and tooling

### Instruction conflicts
- When instruction blocks conflict (delegate to sub-agents vs do not call them; `suggest_git_commit` vs commit-and-push), follow the more specific project or session constraint and state the conflict once.
- When the session allows a single sub-agent call and that reviewer returns an empty or failed response, do not retry past the budget. Do the mechanical schema and coordinate checks yourself, keep the task `in_review`, and name the human or role sign-off that is still open.
- Cursor Agent CLI does not expose the A2gent `tasks` board tool. Claim from `TODO.md` using a ready row with allowed files and `verify`, and do not block waiting for `tasks.next`.

### Edits
- Never run parallel edits against the same file. Serialize replacements and re-read the saved block.
- Before an exact edit, read the live unique block. After any nearby change, re-read again. Stale context is the usual no-match cause.
- In Python, `open(p, "w").write(f(open(p).read()))` truncates `p` before the read and destroys the file, including other sessions' unsaved hunks that no git object holds. Read into a variable first, then open for writing; for a shared dirty file, copy it to `/tmp` before any scripted rewrite.
- Pass the complete file path, not a directory. `read` takes one path per call. `start_line` must be `<= end_line`.
- After inserting a test or helper, re-read neighboring method boundaries and confirm the next `func` / `def` header is still present. Replacing only a header can absorb the following body.
- Discover the actual path before reading. Do not infer filenames from class names, task summaries, or the connected-skills directory. The active guide is root `AGENTS.md`.
- No-op replacements (identical old and new text) are rejected. Apply only a non-empty delta.

### Tool batches and probes
- Never run recursive index/documentation writers in a verification snapshot whose reference folders symlink to the live checkout. They can rewrite live index pages; use an isolated Git worktree or materialize all writable index pages first. Use `git ls-files -z` for filenames with non-ASCII characters rather than parsing quoted line output.
- Check the project Python version before using newer archive APIs: `tarfile.extractall(filter=...)` is not available in the macOS system Python 3.9. For a trusted local `git archive`, omit that newer argument or use the configured Python 3.11.
- If a parallel batch fails before execution (wrong schema, missing tool, malformed path), discard the batch and rerun each check independently. Do not infer repository state from a wrapper error.
- A silent compound shell or heredoc failure is an invocation failure. Split checks into independent commands with captured status.
- `grep` a line that starts with `-` using `--` or `-e`. Guard expected-empty searches with `|| true` under `set -e`.
- On macOS, GNU `timeout` may be missing (exit 127). Use a Python subprocess watchdog. Never kill unrelated long-running processes.
- `code_execution` may isolate helpers and imports. Keep diagnostics inline or use project `python3` via bash.
- Stateful browser actions cannot run through a parallel wrapper.
- Markdown backticks inside a double-quoted bash string are command substitution. Write SQL or task-board updates with Python or a single-quoted heredoc. A backtick path can execute a file and silently blank the intended text.
- `git log -S --all` can hang on this LFS-heavy repo. Scope pickaxe searches to one path and a recent range (`-n 50`) instead of walking every ref.
- A temp-index commit must use the same commit for `git read-tree` and `commit-tree -p`, read right before committing: another session can land a commit in between, and an older base silently reverts its files. Check that `git diff --name-only <parent> <new>` lists only your paths before `update-ref` and before syncing the shared index. In zsh, write `${P}:path`, not `$P:path` (`:a` and friends are history modifiers).

### TODO hygiene
- Board `todo` rows can be months stale. Before claiming, run the row's `verify` command and `git log -n 50 -S '<unique symbol>' -- <path>`. If it already passes, close it with the commit ref, then pick again. For partly done rows, implement only the gap against the contract's acceptance list. Point density and map-content claims at `origin/main`, not a lagging local `main`: R-677's 147 South Quarter plots can already be on origin while the local file still has the pre-strip-plot 28 houses.
- For the current `TODO.md` sectioned format, run `python3 tools/prune_completed_todo.py` to append completed rows to `docs/TASK_ARCHIVE.md`. Do not run `tools/condense_todo.py` unless deliberately migrating to the condensed open-only layout (it rewrites `docs/ROADMAP.md`).
- Map-conversion strict-task IDs (`P0-043`..`P0-046`, `P2-018`..`P2-021`, `P4-014`, `P4-015`) and the `P2-012` -> `P2-021` gate may live in `docs/TASK_ARCHIVE.md`. The audit and conversion-plan validators treat archived full-contract rows as completed. Do not copy archived rows back into `TODO.md` to go green.

### Git and commits
- Inspect `git status` before commit. Unstage unrelated index entries (`M ` in column 1).
- Print `git diff --cached --name-only` immediately before `git commit`. `git add` of your paths does not isolate the commit from a dirty shared index; any leftover staged path goes in. If the cached list is not exactly your claim, unstage and use `git commit -m '...' --only -- <your paths>` (every `-m` before `--`).
- Repo-wide path rewrites must skip `.worktrees/` and `build/`. Prefer scoped `tools/assets/relocate_*_per_model.py` helpers over ad-hoc `rglob` sweeps when colocating GLBs into per-model folders.
- `git commit --only <paths>`: keep every `-m` before `--`. It commits working-tree bytes of those paths, not a prepared index snapshot. Untracked paths must be `git add`ed first; `--only` cannot create a commit from unknown files. For a HEAD-plus-scope commit in a dirty file, keep the scoped bytes in the path through the commit, or commit a temporary index without `--only`.
- In a dirty shared worktree, build a HEAD-plus-scope tree with a temporary `GIT_INDEX_FILE` when the working file has concurrent WIP. Normalize `diff --git`, `---`, and `+++` paths before `git apply --cached`.
- A concurrent session's edit can live *only* in the shared index, with the working file back at HEAD (`git diff <path>` shows the staged hunk being undone). `git reset -- <path>` then destroys work that exists nowhere else. Before unstaging a foreign path, record `git rev-parse :<path>`; after your commit, restore the entry with `git update-index --add --cacheinfo 100644,<blob>,<path>`, which touches neither the working file nor your commit. Some sandboxes refuse to copy `.git/index`, so this blob round-trip is the fallback when a temporary `GIT_INDEX_FILE` is unavailable.
- A regression test must be proven red: revert only the fix and rerun it. A test written from the reasoning that found the bug can pass anyway because another pass masks it (a three-tap smoothing hid a duplicated polyline point), and then it pins an invariant rather than the defect. Say which of the two it is.
- When an isolated verification worktree is fed by copying files from a dirty shared tree, rebuild every shared file from HEAD plus your own hunks each time. Do not re-copy the whole working file: a second copy can bring in another agent's half-finished edits (for example an `#include` of a file that is not there yet) and silently invalidate later tests and captures.
- Never `rsync`/`cp -a` the project root into a throwaway tree: `.worktrees/` and audio make it ~21 GB and fill the disk mid-copy. Copy only the code dirs a test needs (`scripts/ tests/ tools/ content/`), and check `df -h /` first.
- Point that worktree at `origin/main` (or the remote tip), not a stale local `main`. Local `main` can sit a commit behind while another session already pushed. Rebuild long-lived docs (`docs/SEAMLESS_STREAMING_PLAN.md`) from that remote tip plus your hunks; copying the behind working file drops later sections (for example R-1044) and looks like you deleted them.
- A leftover shell cwd in that worktree makes `git status` look detached while the project root is still on `main`. `cd` to the project root before status, commit, or branch moves.
- `git diff --no-index` status 1 is a valid new-file diff. Run whitespace checks separately.
- `git diff --cached --check` rejects Markdown hard-break spaces and an extra blank line at EOF. Strip trailing spaces; keep exactly one trailing newline. Scope the pathspec so unrelated dirty files cannot block the check.
- Staging `scripts/map/**` triggers the map audit. If the hook fails on unrelated scene or TODO drift after scoped checks pass, use documented `SKIP_PRE_COMMIT=1` / `git commit --only --no-verify`. Do not absorb audit WIP. A current `origin/main` failure mode is `verify_map_audit.py` "unknown scenes" for character/storybook `.tscn` files that are not in the conversion plan; that is inventory drift, not a reason to add those scenes to a navigation or host commit.
- On-commit gdlint checks every staged `*.gd` file, including `scenes/**`, and lints the whole file, so touching an older test also fails on its pre-existing long lines. Run `python3 -m gdtoolkit.linter <file>` before committing and wrap those rows too. CI only lints `scripts/*/*.gd`, so `SKIP_PRE_COMMIT=1` is for `tests/`, `tools/`, and scene-script drift that CI does not lint.
- `git commit --only` exports `GIT_INDEX_FILE` into hooks. Fixture-repo Git tests must clear `GIT_DIR` / `GIT_INDEX_FILE` / `GIT_WORK_TREE`.
- On-commit `validate_asset_sources.py` walks the live worktree inventory, not the `--only` snapshot. Unrelated missing SOURCES rows (for example shore PNGs) fail a scoped asset commit even when `assets/SOURCES.csv` is in the path set. After scoped budget/lint checks pass, use `SKIP_PRE_COMMIT=1`; do not absorb that inventory into the claim.
- Do not `git checkout HEAD --` a hot shared file while other dirty scripts already call its new APIs. Do not mid-task `git stash` with fragile pathspecs.
- After `git stash apply --index` conflicts or reports duplicate tracked/untracked paths, keep the stash. Verify every stashed untracked file against `stash^3`, resolve the working-tree conflicts, then reconstruct staged entries from the stash's index parent (`stash^2`) rather than accepting the partially restored index. Merge staged overlaps with the new HEAD separately.
- After a temporary-index commit, move only the branch ref. Do not `git reset --soft` in the live checkout.
- After that commit, `unset GIT_INDEX_FILE` and `git restore --staged -- <your paths>` on the live index. The shared index can still hold those paths as staged deletes or leftover adds; the next shared commit would then revert the files you just pushed. Persistent agent shells keep the export across later commands, including after a failed hook: `unset` before any later `git status` or `diff --cached`, or you will read the temp tree and think the shared index was replaced.
- If a path-limited commit exits silently, inspect `HEAD` and hooks separately before retrying.
- Sync the live index (`git restore --staged`, `git apply --cached` of your hunks into another agent's staged blob) only after checking that `HEAD` moved to your commit. A heredoc commit inside a `set -e` block can fail its hook and still let the next lines run; then reverse what you applied (`git apply --cached -R`). A concurrent agent can also commit your half-finished hunks in its own commit: diff against the new `HEAD` before building your patch.
- A long on-commit map audit can fail with `cannot lock ref HEAD` when another agent lands first. After hooks have already passed on the same path set, rebuild the temp index from the new `HEAD` and retry; `SKIP_PRE_COMMIT=1` is justified for that immediate retry only.
- When several agents relocate GLB folders in one worktree, expect `.git/index.lock`, half-finished `git mv`, and empty asset dirs. Do not `git checkout HEAD -- assets/props/<area>/` until the lock is gone; restore from `origin/main` for that subtree, consolidate duplicates with a filesystem move, then stage only the scoped pathspec before commit.
- Never `git commit --amend` in the shared worktree: another session can commit (and push) between your failed hook run and the retry, and the amend then rewrites their commit with your files. After a hook failure fix the files and make a new commit; if it already happened, `git reset --soft <their commit>` from the reflog and recommit only your paths.

### Godot and Python verification
- Export `GODOT_BIN` in a preceding command (macOS: `/Applications/Godot.app/Contents/MacOS/Godot`). Inline `GODOT_BIN=... "$GODOT_BIN"` expands the old empty value and exits 127.
- Stale Godot tests often fail parse before runtime when APIs move: check enum renames (`RoutineState` -> `ActivityMode`), removed static helpers (`water_surface_height()` -> `MapViewMeshBuilderConfig` constants), and harness helpers (`assert_almost_eq`, `_assert_true` in custom RefCounted tests).
- Typed GDScript parse failures: a later `:=` in a loop (`entry := dir.get_next()`) is illegal after the first declaration, use `=`. Annotate chained `.to_dict()` after `snapshot_state()` as `Dictionary`; that helper returns `RefCounted` and `:=` cannot infer the type.
- Pre-commit runs `verify_map_audit.py` for any staged `scripts/map/**` or `content/maps/**` path. `repository_scenes` and `_declarative_scene_links` compare `SKIP_TREE_PARTS` to `path.relative_to(root).parts`, not the absolute path: a checkout whose own root is `.worktrees/<name>` still discovers `*.tscn` and scene-to-definition links. Nested `.worktrees` mirrors inside a primary checkout stay skipped.
- `tools/run_godot_checked.sh [--require-test-summary] <log-basename> -- <godot-command>`. The log name is a basename, not `/tmp/...`. The command after `--` must start with `"$GODOT_BIN"` (usually `--headless --path .`). Harness `--filter=stem` must come after a second `--` so `OS.get_cmdline_user_args()` sees it; otherwise the full suite runs.
- The harness is `tools/run_godot_tests.gd`. `--filter` matches `test_*.gd` file stems, not method names. Pass one `--filter=stem1,stem2` token. Repeated `--filter name` flags are ignored and the full suite runs.
- `tools/run_map_pipeline_ci.sh` `run_tests` arguments must be those same stems (`test_lower_town_slice_map`, not `lower_town_slice_map`). The helper prefixes `test_` when omitted. A bare stem matches zero files and fails before any test runs.
- Do not regenerate `tests/fixtures/maps/lower_town_slice.parity.json` to hide missing IDs. Restore contract-owned buildings/props first. After a reviewed restore, replace the fixture with `MapParitySnapshot.serialize` bytes (the compare is exact text, not JSON equality). A later contract-owned vegetation ID or a pre-existing `terrain_id_grid_sha256` drift that does not change walkability may land in that same reviewed snapshot.
- Registering a new map in `MapBlueprintRegistry` cascades: drop it from `MapBlueprintAudit.UNREGISTERED_BENCHMARK_SOURCES`, add a card in `docs/data/map_composition_thresholds.json` (interiors: `enforce: false`, `map_class: interior`), run `verify_map_composition.py --write-baseline` for its density row, and rebuild the world layout if an outdoor map gained a transition. `test_transition_visual_contract` then also checks its doors.
- Fresh worktrees need `godot --headless --path . --import` before tests (global class cache). After rsync of `.godot/`, grep `global_script_class_cache.cfg` for the `class_name` the first failing test names (`WorldHostMountQueue` is the usual miss).
- A 30-run leftover can fail on a sibling worker path. Read the crash stack; do not assume it is the named function. When exit is nonzero, ignore a leftover `world_two_seam_trace.json` from the previous successful run.
- Copying only `global_script_class_cache.cfg` into a throwaway worktree is not a substitute for `--import`. The harness summary can go green while `run_godot_checked.sh` fails on missing `.ctex` / `.scn` preloads.
- `--editor --quit-after 2` aborts the filesystem scan before authored `.ctex` files land. Rsync the whole `.godot/` from a fully imported checkout, or run a complete `--import` without an early quit.
- Rsync `.godot/` only from a checkout at the same commit as the worktree. A dirty or behind shared cache makes `class_name` types vanish (`WorldHostMountQueue` not declared) and the first scene launch fails in milliseconds. A shared tree that deleted the `class_name` file is dirty even at the same SHA. When the SHAs differ or the source cache is dirty, run a complete `--import` in the worktree instead.
- A new `elevation_area` / `elevation_ramp` ID on an urban exterior rrmap must land in `URBAN_EXTERIOR_CASES` (`tests/godot/test_r454_elevation_scope.gd`) in the same change.
- Do not run ordinary Node or RefCounted scripts with `--script`; they do not quit. Use the harness.
- A shared worktree with Godot `--editor` or another harness is not a valid test host. Copy only the scoped files into a throwaway worktree (HEAD plus your own hunks) and run the focused `--filter=` there.
- A green focused summary can still fail the checked runner on unrelated parse errors. Report the scoped result separately from the baseline blocker.
- Never launch Godot with a visible window. Use `--headless` for tests, imports, and smokes. Run anything that needs real rendering (captures, render probes) as `tools/godot_render.sh --script <tool>.gd`: it starts the window minimized without focus. Do not hide or minimize the window from a script (it flashes first), and do not write `override.cfg` into the repo root.
- Visual capture helpers can exit 0 despite `SCRIPT ERROR`. Treat output as invalid until the log is clean. Do not run a rendering-capable capture in parallel with another Godot process: concurrent GPU use can write black PNGs that still exit 0. Check file size or pixel extrema before treating plates as evidence. A 1440x810 plate near 20 KiB is an empty or mis-aimed camera, not a valid character shot.
- `gdlint -d` only outside the repo. A root `gdlintrc` shadows `.gdlintrc`.
- CI runs `gdlint scripts/**/*.gd` in bash without globstar, so only `scripts/*/*.gd` is linted. Keep that depth-2 set clean; a passing staged-file hook does not prove the CI glob is green.
- `python3 tools/manage_lfs_assets.py verify` compares indexed LFS pointers to `docs/lfs_assets.json`. After a research plate is recompressed or replaced, update that row's `size_bytes` / `sha256` / `lfs_oid` from `git show :path`. Fetched `plates.csv` rows join the snapshot only when the pointer SHA already matches the CSV.
- `python3 -m unittest discover -s tests/python` collects live-inventory modules that fail on baseline drift. Run the documented fast contract subset on commit.
- Piping unittest to `tail` hides exit status. Use `PIPESTATUS` or a dedicated failure runner.
- Campaign save fixtures with `source_game_state_version` are raw migration inputs. Assert the raw version, or run the `SaveEnvelope` migration path. Do not require raw JSON to equal the current envelope version.
- When a CLI accepts an alternate path, tests must exercise a non-default filename and assert the selected basename.

### Task board
- Identity is the internal `R-*` ref, not a product ID (`P0-122f`) or a prose label (`R-454a`). Resolve with `tasks.list` before `tasks.get`.
- `tasks.next` does not honor complexity or role filters. Restore a wrongly claimed row with its full body, then claim the exact ref.
- If `tasks.create` fails with `UNIQUE constraint failed: tasks.project_id, tasks.ref (2067)` (2067 is the SQLite code, not a ref), the project's `max(seq)` lags its highest `R-*` ref. Check `select ref, seq from tasks where project_id=... order by seq desc limit 3` in `aagent.db`, set the top row's `seq` to its ref number, and retry. Never create board rows in parallel.
- Create dependency chains sequentially and verify each returned ref. An empty `body` on update erases the contract. If a mutation times out, query the exact ref before retrying.
- `tasks.create` assigns the next ref itself and ignores any ref in the title or body. When a new task pack needs matching `R-*` ids in `TODO.md` and its contract docs, create the board rows **first**, then write the returned refs into the docs. Guessing "last ref + 1" is wrong whenever another session has landed rows since; renumbering afterwards is a multi-file rewrite that must run as one ascending-order pass (`R-949->R-947` before `R-951->R-949`) or earlier substitutions get clobbered by later ones.
- If every `tasks` action fails with `Scan error on column ... "updated_at": unsupported Scan, storing driver.Value type string into type *time.Time`, some rows hold unparseable timestamp text (Go `time.String()` like `... +0000 UTC`, or `... +0300`). Back up `aagent.db`, then rewrite `created_at/updated_at/started_at/completed_at` to UTC `YYYY-MM-DD HH:MM:SS`. When editing the board by raw SQL, always write that format (`strftime('%Y-%m-%d %H:%M:%S','now')`).
- When the `tasks` tool is unavailable in Cursor, claim and update through Brute `PATCH http://127.0.0.1:5445/projects/{project_id}/tasks/{ref}` with the full body (`title`, `body`, `status`, `priority`, `complexity`, `tags`). An empty `body` erases the contract. Read the board with `sqlite3 -readonly ~/.local/share/aagent/aagent.db`. Do not infer open work from `TODO.md` alone, and do not write that database. `GET /projects/{id}/tasks?ref=R-NNN` is a list filter that can return a different row. Fetch one task with `GET /projects/{id}/tasks/R-NNN`.
- Do not `POST` a dummy task to learn the Brute create schema. `GET` an existing ref instead. A probe create consumes the next `R-*` number; reuse that ref for the real follow-up rather than cancelling and creating another.
- Before coding an open `R-*` row, grep `TODO.md` for the product ID (`P0-226`); if it is already `[x]`, run the task `verify` clause headlessly and close the board row instead of re-implementing.
- Before filing a leftover named in a review contract, read that leftover ref on the board. A later sibling may already be `done`; do not open a duplicate.
- A contract that says the maintainer must name a scope trade, or "do not pick it on their behalf", is a hard skip even when the rest of the row is docs-only. Pick a different completable row.
- Parser or compiler blockers filed as open `R-*` rows may already be fixed on `main` while reports still cite August diagnostics. Run `test_map_rrmap_parser`, `tools/validate_map_blueprints.gd`, and the named focused suites before landing duplicate parser work; close with a dated `docs/reports/r*_*.md` ledger when code is already green.
- Before raising a task pack, list `docs/tasks/` **including untracked folders** (`git status --porcelain docs/tasks/`). A sibling pack raised the same day from the same maintainer complaint is likely, and it will not be in `TODO.md` or the docs report yet. When one exists, write an explicit ownership seam table into both READMEs (who owns map data vs runtime geometry vs materials) and name any row pair that targets the same map as must-run-in-sequence. Two packs that both say "high priority" on `lower_town_slice` and both demand a clean `git diff --stat content/maps/` cannot both run.
- Regenerating `docs/reports/active_markdown_report.md` for your own new docs also picks up every doc another uncommitted session added, because the report counts all active Markdown. That is correct and the `--check` gate requires it, but say so in the commit message so the file's diff is not read as scope creep.

### Documentation, provenance, and evidence
- `tools/validate_content.py` validates JSON corpus roots, not Markdown reports.
- Hub indexes such as `history/RESEARCH_INDEX.md` have their own heading and link contract, not generic front matter.
- The active-doc excluded inventory is Git-tracked Markdown only (`build/` and untracked notes must not change it). Still regenerate `docs/reports/active_markdown_report.md` from a clean HEAD worktree when active docs themselves change; never from a dirty tree whose `TODO.md` or `docs/` links would rewrite the committed counts. Staging a new `docs/reports/*.md` increments that excluded count; regenerate the report after `git add`, not before, or the on-commit `--check` fails with "not up to date". `git ls-files` follows `GIT_INDEX_FILE`, so after a temp-index `read-tree` regenerate with that env set and add the report into the same index. A report built from the live index (other sessions' staged Markdown) will fail the hook. The on-commit `--check` still reads live `TODO.md` from disk, so a report that is correct for HEAD plus your new excluded file still fails while another session has dirty `TODO.md`. Prove `--check` in a HEAD worktree, then `SKIP_PRE_COMMIT=1` for that scoped commit. When committing through a temporary `GIT_INDEX_FILE`, run the generator with that same variable exported (it lists docs via the index), then `git add` the report into the temp index; the on-commit `--check` sees the temp index too.
- Staging `TODO.md` does not trigger the on-commit active-docs check. That hook only runs for `README.md`, `AGENTS.md`, `docs/CANON.md`, the report, or the generator. Do not stash `TODO.md` to isolate a red `--check` on a dirty shared tree.
- Rights-sensitive media requires record-level commercial terms or written permission. Regional metadata or CC BY-NC is not enough. Preserve the verified fallback.
- Prefer dated face plates under `docs/reports/images/characters/face_*.png` over older `closeup_*.png`.
- Never rewrite all of `assets/SOURCES.csv`. Append or replace only target rows. SHA-256 lives in `prompt_or_url`. `csv.writer` defaults to CRLF even on macOS; pass a Unix `lineterminator` when appending.
- Do not commit provenance for untracked WIP assets. Do not overwrite `build/act1/rr.dmg`.
- Tracked `generated/` is not uniformly disposable. Classify into runtime, rebuild inputs, retained evidence, and disposable intermediates before deleting.
- `Path.write_text()` in this environment has no `newline=` keyword. Normalize line endings in the content or use `open(..., newline="\n")`.
- Retiring superseded fauna GLBs requires the same sweep as adding them: update `MODEL_PATHS`, bird authored-pose expectations, `SOURCES.csv` (parent GLB plus Godot-extracted sidecars), gait allowlists, and asset-library tests that still filter `animals/` instead of `storybook/`. Relocate still-live livestock into `assets/storybook/` before deleting `assets/animals/medieval/`.
- Nine `BROKEN_LINK` issues in root `README.md` with `../../` targets usually mean the product README was overwritten by `assets/characters/README.md`. Restore from the parent commit (`git show <parent>:README.md`) instead of rewriting links in place.
- When moving GLBs into per-model subfolders, update paths with a scoped script (parent directory prefix + model name), not repo-wide `hammer.glb` / `sword.glb` string replaces. Those hit unrelated props and storybook equipment. After regex fixes on `.import` sidecars, rewrite `source_file=` from the folder basename; never use `\1` in shell-quoted Python replacements. Run Godot headless `--editor --import` before storybook Godot tests; imported `.scn` caches still point at old extracted texture paths until reimport.
- Path-rewrite scripts must exclude `.worktrees/`, `build/`, and other non-canonical trees; `Path.rglob` from repo root will dirty sibling worktrees and backup CSVs. For `assets/SOURCES.csv`, restore from `HEAD` and apply a prefix-scoped replace for the moved folder only. Stage with explicit paths (`git add assets/props/trade/...`); a dirty index can sweep unrelated prop migrations into the same commit. Split asset moves and loader/generator path updates into one commit when possible so runtime does not briefly point at missing flat paths.
- Commit verified work as soon as it is proven. A concurrent agent session running `git stash` wipes the whole uncommitted working tree, including files it has no interest in. Recover from `git stash list` (`git show 'stash@{N}:<path>'`), and re-derive generated artifacts from their generator rather than trusting a recovered binary - regenerating and matching the recovered SHA-256 also proves the generator is deterministic.
- A concurrent session can rewrite a shared facade file (for example `map_view_materials.gd`) from its own staged copy and drop your unstaged additions. Before capture, test, and commit, grep for your new symbols and re-add them as an unstaged hunk, without touching the other session's staged content.
- Brand-new **untracked** files a concurrent `git clean -fd` deletes are not in `git stash list` and not in the stash's untracked tree (`stash@{0}^3`). If you ran `git add` even once, git already wrote their blobs: recover with `git fsck --lost-found`, then match `.git/lost-found/other/*` by `git cat-file -p <oid> | head -1` against each file's first line and write them back. This is the strongest reason to `git add` and commit a new doc or asset set the moment it is written, not after the verification pass.
- When the shared `TODO.md` holds two sessions' unrelated pack sections, do not `git add TODO.md`. The working tree is untouched, so their section survives. Afterwards **re-check the main index**: it may still stage their older copy, which now reads as a deletion of your just-committed section. `git add TODO.md` once your section is in `HEAD` resolves it to their diff alone.
- A board claim (`in_progress`) does not prove exclusivity: a parallel terminal session may implement the same task without claiming it. Before writing a task's new files, check `git status` and mtimes of its allowed paths; if another session is actively writing them, hand off review notes in the task body and pick a non-overlapping task instead of racing on the same file.

Run the whole swap inside one `bash -c '...'` with arrays and `set -e` up to the backup step. A zsh multi-path variable that does not split can silently skip the backup and the checkout.
- `git add <paths>` does not isolate a commit: the shared index can already hold stale entries, for example left behind when another session committed through a temporary `GIT_INDEX_FILE`. They then commit as silent reverts of that session's work. Right before `git commit`, run `git diff --cached --name-only` and require it to list only your paths; otherwise commit with a temporary index built from `HEAD` plus your paths. If a revert already landed, restore just those paths with `git restore --source=<their commit> --staged -- <paths>` and a follow-up commit, and never force-push.
- Godot scans `build/` as `res://` (gitignored, not ignored unless a folder has `.gdignore`). A scratch `class_name` copy steals the global class cache ("Class X hides a global script class"). Keep backups outside the project or under `build/scratch/` (`godot_render.sh` creates that `.gdignore`). Do not add `build/.gdignore` at the root: capture tools read and write `res://build/`. `run_pre_commit_checks.sh` and `run_godot_tests.gd` fail fast on unignored `build/**/*.gd` with `class_name`, or on cache paths outside `scripts/`, `tests/`, `tools/`, `assets/`, `scenes/`, `addons/`. - Board refs and `TODO.md` row ids share one `R-NNN` namespace but are allocated independently: the board auto-assigns the next ref on create, while `TODO.md` only shows rows someone wrote down. `grep`ing `TODO.md` for the highest `R-` therefore under-reads the real high-water mark, because a concurrent pack may already hold board refs that never reached `TODO.md`. When renumbering an overlapping range with `sed`, substitute highest-first so new values cannot be rewritten twice.
- Check `docs/tasks/*/` and `docs/adr/` for in-flight sibling packs before reserving ADR numbers or writing a task pack. Validate your own pack by moving the other pack aside and regenerating the report, then decide with the maintainer whether to commit both packs together or hold `TODO.md` back and rely on the board rows.

- Never `git stash` source files while a background Godot test run or capture is still executing: the run loads scripts lazily and silently mixes old and new code. Serialize before/after comparisons as stash -> run -> pop -> run in one foreground command, and compare failing-test sets (`comm -13 base mine`) instead of totals, because main carries many pre-existing failures.

Keep scratch probes outside the project (`--script /tmp/probe.gd` works). Find it read-only with `select ref from tasks where started_at='' or completed_at=''` and ask the maintainer to null those two fields. Before retrying, list files of every new upstream commit, 3-way merge the overlapping ones (`git merge-file <live> <old-base> <new-HEAD>`), restore upstream-only files with `git checkout HEAD -- <path>`, then commit through a temporary index (`GIT_INDEX_FILE=/tmp/x git read-tree HEAD`, add your paths, regenerate `active_markdown_report.md` under that index, commit) and `git reset -- <your paths>` in the real index afterwards.

Put the probe in a temporary `tests/godot/test_zz_*.gd` and run it through the harness with `--filter=`, then delete it.

- To commit only your hunk of a shared file that other sessions also edit (TODO.md, playbooks), back up the working copy, write HEAD plus your hunk, run `git commit --only -- <paths>`, then write the backup back (re-adding your hunk if it is missing). Skipping the restore silently erases the other sessions' unstaged edits. If HEAD moves between attempts, rebuild the file from the new HEAD.

Put throwaway probes in a non-ignored folder (such as `build/dbg/`), start work from `call_deferred`, and redirect output to a file instead of piping it through `grep | head`.

Before reviewing a capture set, check the files actually differ (`md5 -q <files>` or compare sizes) and that the log printed one line per shot; re-run the capture if they are identical.

### Long-running verification
- Host verification can outlive the parallel wrapper's deadline. Write per-step logs and exit statuses under build/ and inspect the worker PID before retrying; a caller timeout is not a test result.

### Shared worktree hygiene
- Before committing, check `git diff HEAD --stat -- <file>` for every file you touched: another session can leave the index and working tree on an older base than HEAD, so a plain `git add` would revert recent commits. Port your change onto HEAD in a throwaway `git worktree` (`--import` once, then test there) and commit from it.
- Never use an unquoted shell variable as a git pathspec list in zsh (it is not word-split) and never `git stash pop` after a `stash push` you have not confirmed succeeded: it pops an unrelated older stash.
- A tool that rewrites a JSON evidence manifest can break the very contract test that guards it: Godot's JSON writer sorts object keys, so `tools/capture_r715_water_acceptance.gd` reorders `visual_checks` away from the order `test_r715_water_acceptance_packet.gd` asserts, writes `width`/`height` as floats, and flips packet-level `capture_status` out of fail-closed on a single-plate run. After running any manifest-writing capture tool, check `git diff HEAD --stat` on the manifest: a two-plate update that produces thousands of changed lines means the writer reordered the file. Rebuild the manifest from the committed version with only the real field changes applied, then rerun the packet test before committing.
- When the acceptance tool and the whole-suite gate disagree, split the evidence: run the narrow `--filter=` set that your change actually covers and report it as green, and report the full-suite failure count separately with what else is in flight (`git diff HEAD --name-only` by area). Do not call a full suite "pre-existing failures" without naming the concurrent files that explain it, and do not claim the epic's no-regression gate is met from a filtered run.
- Do not use `git pull --rebase --autostash` before pushing in the shared tree: the autostash reapplies other sessions' work without `--index`, so their staged paths come back unstaged. Use `git pull --rebase` only when the tree is clean, otherwise `git fetch` and push or rebase from a throwaway worktree.
- When cloning an existing tool or test as a template, read the source with `git show HEAD:<path>`, not the working copy: another session may have uncommitted edits in it (extra shots, renamed outputs), and a sed-based copy silently inherits them.
- A headless `godot --script` run that hits a script error drops into the interactive debugger and waits on stdin, so the tool call hangs until its timeout. Always run Godot with `< /dev/null`; macOS has no `timeout`, so wrap long runs in a background PID loop that kills the process after a deadline.
- `tools/generate_active_docs_report.py` counts tracked files, so its `--check` result changes after `git add`. When a commit adds a new Markdown file, stage it first, then regenerate the report and stage that too. If other sessions have uncommitted docs, generate the report in a clean worktree (HEAD plus your files), commit there, move `main` with `git update-ref refs/heads/main <new> <old>`, then `git reset -q -- <your paths>` in the shared tree and reapply any staged hunks other sessions had on those paths (`git diff --cached` saved beforehand).
- When other sessions' uncommitted edits break compilation of the shared tree, test in a shadow project instead of waiting: symlink every top-level entry except `scripts/`, `tests/` and `.godot/`, extract `scripts/` and `tests/` with `git archive HEAD | tar -x`, copy your changed files over them, symlink `.godot/imported`, and copy `global_script_class_cache.cfg` and `uid_cache.bin`. Re-copy your files before every run.
- In the shared tree never commit the whole index: another session can stage files (even deletions) between your `git add` and `git commit`, and they ride along into your push. One bird commit deleted a file that `map_view_3d.gd` in HEAD still preloaded and broke `main`. Commit with `git commit --only -- <your paths>` (works with `--no-verify`), then check `git show --stat HEAD` before `git push`.

- The text `read` tool does not preview PNG files: it emits binary noise. Use a visual-capable image viewer; if the tool returns only a screenshot path, do not claim visual inspection. Keep image comparison pending until a reviewer can see the pixels.

- Partial commits (`git commit -- paths`) run the hook against a temporary index, so `generate_active_docs_report.py --check` sees only HEAD plus those paths. Regenerate the report under `GIT_INDEX_FILE=<tmp>` (`git read-tree HEAD`, `git add` own paths) before committing, otherwise it reports "not up to date". gdlint failures in files another agent staged are not yours: commit only your paths.

- A task ref you find in uncommitted work is not proof the task exists: a crashed session can leave `R-NNNN` comments whose number belongs to an unrelated board task (a well removal cited `R-1192`, which is the seasonal-ground task). Look the ref up with `tasks.get` before reusing it, and create your own task when it does not match. The same holds in the other direction: never write a *future* follow-up ref into shipped metadata (an `assets/SOURCES.csv` status, a doc Limits bullet, a code comment) by guessing the next number - a concurrent pack probably already holds it. Call `tasks.create` first and paste back the ref it returns.
- Commit a regenerated fingerprint artifact (`content/world/reval_outdoor_layout.json`, evidence manifests) in the same commit as the source it hashes. A concurrent session sweeping the tree will commit the artifact alone, leaving `main` with a manifest whose `source_sha256` points at a file that is still uncommitted, so `verify_world_layout.py` passes locally and fails on a clean checkout. If git reports your rebuilt artifact as clean against HEAD, check `git log` first: HEAD may have moved under you.
- Scene-inventory verifiers (`verify_map_audit.py`, `verify_map_conversion_plan.py`) walk the filesystem, not the index, so another session's gitignored `build/<task>/baseline/*.tscn` benchmark output makes them fail with "missing scene coverage" for scenes you never touched. Check whether the listed paths are under `build/` and untracked before treating it as your regression.
- In this shell `ls` is aliased to `eza`, so `$(ls -A | grep ...)` loops (shadow-project setup) silently match nothing and later steps run against an empty tree. Use `/bin/ls` (and `/bin/cp`) in scripts.
- `git stash` / `git stash pop` inside a temporary worktree drops the index: everything comes back unstaged, and a following `git commit` records only the files that were untracked-then-added. After any stash round trip, `git add` your paths again and check `git show --stat HEAD` before rebasing or moving `main`. Prefer `git diff --cached > patch` over stash for a baseline check.
- A temporary-index commit takes its parent from HEAD at commit time, not from the `read-tree HEAD` snapshot. If another session commits during the pre-commit hook, your tree silently reverts their files. Run `git read-tree HEAD` right before `git commit`, then confirm `git show --stat HEAD` lists only your paths. If a revert lands, restore from their commit in a follow-up commit.

Fix every stage first (gdlint at `~/Library/Python/3.9/bin`, SOURCES.csv, texture `prompt.json`, `generate_quest_package_tests.py`, `generate_active_docs_report.py`), regenerate the docs report last, then commit once; if HEAD moved only, retry with `--no-verify` right after a green run. gdlint `# gdlint: ignore=` does not cover `max-file-lines`; raise it in `.gdlintrc`. Stray `build/*/baseline` project copies break the map audit - delete them.

- `tools/run_godot_tests.gd -- --filter=` matches exact comma-separated file stems (`test_tree_leaf_fall`), not substrings; a partial name silently finds nothing. Use `/Applications/Godot.app/Contents/MacOS/Godot` since `godot` is not on PATH, and never run the whole suite in the foreground (it exceeds 10 minutes).

- `--resolution WxH` sizes the window, not the viewport: `root.get_texture().get_image()` comes out at the project's 1920x1080. Resize the image to 1280x720 before `save_png` when the plate is evidence.

- Terrain height queries must triangulate exactly like the mesh that is drawn (same quad diagonal rule); bilinear lookups on a triangulated mesh sink actors on lumpy ground. Rivers from a DEM plate need a water level that follows the land, not sea level, or banks become gorges and bridges hang mid-slope.

- Godot binary on this Mac is `/Applications/Godot.app/Contents/MacOS/Godot` (not on PATH; `ls` is aliased, so verify with absolute paths).

- Replacing a ground plate: CO-01 ground texture arrays need one layer size per map type (grass albedo 2048, normal and roughness 1024, tests enforce it), and `godot --headless --import` must run after rewriting a PNG or tests read the stale imported size. macOS has no `timeout` and BSD `sed -i` needs `-i ''`; use Python for file edits. After another session adds a `class_name` file, run `godot --headless --path . --editor --quit` before a render capture.

- Godot probes via `--script` cannot reference autoloads (e.g. `DoorNavigator`) at compile time: `await process_frame` first and use `load()`, or write a throwaway `tests/godot/test_*.gd` and run it with `--filter=`. Delete it afterwards.
- When `git pull --rebase` aborts on a dirty shared tree, push through a temporary `git worktree` on `origin/main` with `git cherry-pick <sha>`, then remove the worktree. Never stash or reset others' changes.
- Another session's `git commit` has no pathspec, so it takes **the whole index**, including whatever you have staged. Staging and then doing anything slow (a lint fix, a render, a test run) can lose your change set into someone else's commit message. Stage and commit in one shell invocation, and if a gate rejects the commit, `git reset` your paths back out of the index before fixing the problem. The repo also takes the index lock during their commit: poll `.git/index.lock` instead of retrying blind.
- To keep a shared doc file out of your commit while another session edits the same page: rebuild `git show HEAD:<path>` plus only your own edits into a temp file, `git add` that, then restore the full working copy. Do not try to separate hunks after the fact.
- Before naming a new ADR, `git fetch` and list `origin/main:docs/adr`: parallel sessions take the next number. In a cherry-pick worktree, regenerate the shared ADR index with `python3 tools/docs_index.py` instead of hand patching, and use `sed -i ''` on BSD.

- Before editing a shader, confirm which one draws the surface: render a capture after the edit and diff it against the "before" shot. City ground is `scripts/city/city_ground.gdshader`, not `map_view_terrain_blend.gdshader` (map view only). A shader that fails to compile renders white; check `SHADER ERROR` in the `godot_render.sh` output.

- Before `git commit` run `git diff --cached --stat`: another session may have staged files in the shared index, and a plain commit sweeps them in. Commit with explicit paths (`git commit -- <paths>`) so only your files go in.

- Image generation: `openai_generate_image` may fail with "no credits"; its `quality` accepts low/medium/high/auto, not "hd". Fall back to Leonardo, and always name the period style in the prompt ("Romanesque / early Gothic, flat figures, no text"); an unqualified "Gothic stained glass" returns Victorian revival art with gibberish lettering.

- The staged pre-commit hook runs `docs_index --check` over the whole tree, so another session's untracked orphan `.md` blocks every commit. Run the remaining gates that match your paths by hand (gdlint passed in the hook already; e.g. `tests.python.test_magic_budget`, storage hygiene), then `git commit --no-verify -- <your paths>` and say so in the report. Do not link or delete the other session's file.
- When the one allowed review delegation fails (empty sub-agent reply), do not retry it: self-review the diff for state leaks across close/retry/re-open and add a regression test for each edge you find.

- Terrain with a sudden scarp: before smoothing or carving the heightfield, dump `asl` at each build stage (a throwaway wrapper that exec()s the script with `dbg()` calls) to find which stage creates it. A 9 m "scarp" on the south approach was a non-periodic wrap in `terrain_relief.lattice_noise`, not DEM data; a slope-relaxation pass placed before the culprit stage changed nothing. Run the city plan builder with `/usr/bin/python3` (has numpy/PIL) and without `-I`.
- Leonardo hosts partner models only on its v2 API (`tools/generate_leonardo_v2_image.py MODEL W H OUT prompt`): `gemini-2.5-flash-image` (Nano Banana, best for flat period art, strict sizes e.g. 832x1248) and `gpt-image-1.5`. The `leonardo_generate_image` tool is v1-only (its own models) and returns 500 for these names. The image CDN needs a browser User-Agent.

- A scene that is black after a transition: first load its root script headless (`load()` in a throwaway test) - a parse error in the destination script silently strands the player; check before debugging input/skip logic.

- To throw away your own edits to a file, restore the index version (`git show :<path> > <path>`), never `git show HEAD:<path> > <path>` or `git checkout HEAD -- <path>`. Plain `git diff` compares against the index, so another session's staged hunks in that file are invisible to it, and resetting to HEAD silently deletes them from the working tree (their next commit, or yours, then reverts them). Check `git diff --cached -- <path>` before any reset.

- Standalone shader capture scripts: `await process_frame` before building nodes under `root`, and call `Camera3D.look_at` only after `add_child`; otherwise the viewport renders blank white and the look_at is ignored. CPUParticles3D has no `amount_ratio` (GPUParticles3D does); quantise `amount` instead.
- The text `read` tool does not decode PNGs: it returns binary text, not visual evidence. Use a browser/media preview and publish the capture path; do not claim visual inspection from raw bytes or a screenshot tool that only returns a filename.
- When explicitly staging approved capture PNGs below ignored `docs/reports/`, use exact file paths with `git add -f`; do not force-add the whole generated evidence directory.

- Before debugging a render bug, check the Godot binary works (`/Applications/Godot.app/Contents/MacOS/Godot --version`). It was once a self-referencing symlink (`godot -> Godot`, "Too many levels of symbolic links"); without a renderer, do not guess shader fixes - report it and ask for the camera pose instead.
- macOS is case-insensitive: `ln -sf Godot .../MacOS/godot` overwrote the real `Godot` binary with a self-referencing symlink. Never create a differently-cased alias next to a binary; put a wrapper on `PATH` or call the absolute path `/Applications/Godot.app/Contents/MacOS/Godot`. Recovery: download the matching release into a fresh temp dir and copy the executable back.

- Render captures (e.g. `tools/capture_ws08_shore_swash.gd`) can hang >10 min while other sessions load the GPU/map; run them in the background with a bounded wait and fall back to a narrow headless contract test instead of blocking.
- If a Godot GPU capture logs map-registry validation errors before scene creation, treat the capture as invalid and stop the run; verify the target map ID and active transition registry before retrying instead of waiting on the broken render loop.
- Never edit a shell script while a background run of it is still executing: bash reads scripts incrementally, so the running loop picks up half-old, half-new lines and dies with a syntax error mid-matrix. Write a new script file for the next step instead.
- Before trusting a benchmark or capture tool, grep its log for `Cannot open file` / `Failed loading resource`: tools that load retired scenes or map definitions can hang forever or exit 0 with an empty report. Check `ps` for orphaned Godot processes from such runs.
- macOS EDR headroom (`Window.get_output_max_linear_value()`) is dynamic and per screen: a minimized `godot_render.sh` window can read 1.0 or 4.0 on the same XDR panel between runs. Record the headroom at the moment of each read-back, select the screen explicitly, and repeat the run; the RenderingServer GPU timer also reads 0 for that window, so measure wall frame time with vsync off.
- zsh does not word-split an unquoted `$VAR` holding several paths, so a `for f in $F` swap loop runs once on one bogus path and silently swaps nothing. Use a bash array (`bash -c 'F=(a b); for f in "${F[@]}"; ...'`) and grep for a marker after a swap before trusting a "before" capture.
- A commit that stages only some hunks of a shared shader can leave HEAD uncompilable (R-1443 left an `#include` in the middle of `sky()`). Before building "before" plates or committing partial hunks of a file, compile HEAD's version of it, and ship the minimal placement fix with your own hunks if HEAD is broken.
- `git checkout -- <paths>` aborts the whole restore if any pathspec is untracked or gitignored (e.g. `docs/reports/images/city/*.png`), so a temporary edit to a tracked tool listed with them stays in place. Restore tracked files in their own `git checkout`, then grep for the reverted value.

### Aggregate commit gates
- For an all-changes commit, run staged hooks unchanged, fix whitespace and lint on the complete staged files, and regenerate documentation only after repairing broken targets. A card-selection plan is not proof that a card file exists; generated links must check authored files. Retired household links must not invent replacement census IDs.
- Headless camera tests must explicitly set the camera mode they exercise: persisted user settings can otherwise change the mode between local runs. Keep fixture houses independent of retired map definitions so tests cannot become vacuous.
- Committing around another session's staging with a temporary `GIT_INDEX_FILE`: build each blob in its own step and check it is non-empty (`git cat-file -s`) before `commit-tree`. `set -e` does not catch a failing filter inside `$(... | git hash-object -w --stdin)`, so an assertion silently writes an empty blob. Never redirect a filter's output straight onto a tracked file. Grep the generated report at HEAD first: it may already contain your entry. In multi-line shell scripts, guard `cd` with `|| exit 1`, because the lines after a failed `&&` chain still run in the wrong directory.

- When a coding delegation (`delegate_to_agent`) dies with an empty provider response, do not burn turns re-delegating: implement the prepared brief directly in the main session and note the provider incident in the report. The brief doubles as a spec, and a single review delegation can still follow the implementation.

- Sub-agent delegation can fail with an empty final response (provider/CLI glitch, no tool calls). Retry the delegation once with the same spec; if it fails again, implement the smallest verifiable slice in the main session or hand the spec off via a follow-up session card instead of re-delegating the whole spec.
- Never `Read` a full-size render (1600x900 PNG, a 1 MB contact sheet) into the conversation: one oversized image response aborted a whole session with an LLM error and lost its final steps. Downscale first (`magick in.png -resize 960x540 -quality 72 /tmp/x.jpg`; `magick montage a.png b.png -tile 2x2 -geometry 480x270+2+2` for clip frames) and read the JPEG.

- Pathspec commit with a shared index: the pre-commit `active_markdown_report.md` check runs `git ls-files` against a temp index (HEAD + your paths), so a report generated in the busy working tree is "not up to date". Generate it with `GIT_INDEX_FILE=/tmp/x git read-tree HEAD && git add -f <your paths>` first, then stage the report. In zsh, keep path lists in arrays (`P=(...)`, `"$P[@]"`/`$P`), a string variable is not word-split.
- Never round-trip hand-formatted JSON (for example `content/audio/sfx_catalog.json`) through `json.load`/`json.dumps`: it reflows every inline array and turns a 6-entry addition into a whole-file diff. Insert the new entries as text before the closing `]` and run the validator.
- When `git push` is rejected and the shared working tree has other sessions' uncommitted edits in files the remote commits touch, do not pull into it. Merge in a throwaway detached worktree (`git worktree add --detach /tmp/x origin/main && git merge <your-commit>`), push `HEAD:main`, remove the worktree; local `main` stays an ancestor and fast-forwards later.
- If a delegated sub-agent returns an empty response, do not retry the same delegation: it has failed the same way twice in a row. Do the work yourself and keep the single review slot for after the change.
- zsh applies history modifiers to unbraced variables: `git push origin $m:refs/heads/main` expands `$m:r` and pushes a garbage refspec. Brace variables before a colon (`"${m}:refs/heads/main"`).
- When `origin/main` itself cannot load a scene (another session committed callers of a facade or shader change that is still only in the shared tree), verify in a second throwaway worktree: `origin/main` + `git diff --binary origin/main -- scripts scenes ...` from the shared tree (excluding your own paths) + your files. Commit only from the clean worktree with your explicit paths, and report in the commit and task that the gate ran on that overlay.
- A shader that renders flat white (or default grey) with `SHADER ERROR: Tokenizer: Unknown character #35: '#'` means its preprocessor failed and Godot compiled the raw text: list every `#include` of that shader and check the files exist on the commit (`city_ground.gdshader` broke this way when `water_capillary.gdshaderinc` was only in the shared tree). Probe with a throwaway `--script` that assigns the preloaded shader to a `ShaderMaterial`; fix the missing file, not load order.

- `git commit-tree` runs no hooks. After a temp-index commit, run the gates the hook would have run on your files yourself (`python3 -m gdtoolkit.linter <files>` for 100-column GDScript, docs checks) before pushing, and compare against the parent version so you only fix what you introduced.

- zsh does not word-split unquoted `$var`: `set -- $cfg` or `for a b in $pairs` passes one string, and a `sed -E "s/= [^;]+;/= $1;/"` sweep then writes garbage (or an empty value) into the file. For parameter sweeps call a function with explicit arguments (`run 4.0 2.5`) and edit with a Python regex that tolerates an empty value; `grep` the edited line before each run.
- When the local `main` has diverged from `origin/main` and the tree is dirty, do not rebase or stash: `git worktree add /tmp/<name> origin/main --detach`, run `Godot --headless --path <wt> --import` once, work and push from there. Verify "no new failures" by diffing the failing-test list with `git stash -u` in that worktree.
- In zsh never name a loop variable `path` (`while read oid path`): it is tied to `PATH`, and every later command fails with `command not found`. Use `fpath`/`file`.
- In zsh, `$var:r...` applies a history modifier (`:r` strips an extension), so `git push origin $sha:refs/heads/main` pushes a mangled ref. Brace it: `"${sha}:refs/heads/main"`.
- If `git pull --rebase` aborts because another session's untracked files would be overwritten, do not delete or stash them. Cherry-pick your commit into a temporary `git worktree add --detach <tmp> origin/main`, push `HEAD:main` from there, and remove the worktree. Later rebases of local `main` drop the duplicate as an already-applied cherry-pick.
